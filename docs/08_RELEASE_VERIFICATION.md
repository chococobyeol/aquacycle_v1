> 갱신일: 2026-07-26
> 대상: 현재 작업본의 미션 1~7, 실험실, 생태·물질 순환 및 관찰 기능

이 문서는 과거 어느 시점의 통과 개수만 남기는 기록이 아니라, 현재 배포본에서
무엇을 실제 문제로 판정하는지와 같은 검사를 다시 실행하는 방법을 함께 고정한다.

> **현재 배포 판정:** 2026-07-24의 옛 송사리 미션 7 완료 판정은
> 장주기 먹이망 진단 뒤 철회했다. 2026-07-25에는 미션 7을
> 식물플랑크톤–물벼룩 세대 연결 과제로 교체하고, 부유 분해균을
> 저품질 보조 먹이로 연결한 새 자동·화면 검증을 추가했다. 2026-07-26
> 물벼룩 물질 규모와 여과·번식·밀도 피드백을 다시 보정했으며, 아래 두
> `7,200초` fixture와 전체 지급 `14,400초` 확장 검증을 **통과**했다.

## 1. 배포 전 일괄 검증

```text
npm run verify:release
```

이 명령은 다음 순서로 실행된다.

1. TypeScript 정적 검사
2. 현재 저장소에 등록된 전체 자동 회귀를 단일 작업자에서 실행
3. 미션 6 생산자·미생물계의 낮·밤 50주기 확장 검증

단일 작업자는 모델을 느슨하게 만드는 설정이 아니다. 서로 독립적인 장시간
시뮬레이션들이 같은 CPU를 동시에 차지해 성능 제한시간만 넘기는 거짓 실패를
막는다. 64배속 계산량과 Worker 성능 계약은 각각의 전용 시험에서 그대로 검사한다.

## 2. 생태 검증 작성 규칙

- 과제 해법 검증은 목록에서 항목을 고르고 수조에 놓는 공개 명령만 사용한다.
- 정상 플레이에서 만들 수 없는 방식으로 모든 셀의 생체량을 직접 채우지 않는다.
- 광원 출력 숫자가 크다는 이유만으로 생산성이 높다고 가정하지 않는다. 종별
  광반응을 지난 실제 생산량·생체량·누적 섭식량을 관찰한다.
- 순간 개체 수 하나로 숨은 수용량을 추정하지 않는다. 출생 기록, 실제 섭식,
  세대교체와 기술 안전선이 생태 판정에 개입하지 않는지를 나눠 확인한다.
- 새우 개체군의 멸종과 탄소·질소·산소 등가 장부 누출은 별개로 판정한다.
- 미션 해법은 특정 장식 배치를 강요하지 않되, 공급된 먹이를 볼 수 있는 위치에
  배치하는 것처럼 플레이어가 화면에서 판단할 수 있는 행동으로 구성한다.

단위 수식 시험은 필요한 상태 하나만 고립하기 위해 내부 값을 설정할 수 있다.
그러나 그 결과를 그대로 과제의 플레이 가능성이나 전체 생태 평형의 증거로 쓰지
않는다.

## 4.1 최신 미션 7·관찰 검증

기존 `4,800초` 검사는 마지막에 몇 마리가 남았는지만 확인해, 후반부에
실제로 출생·성숙이 멈춘 군집이나 먹이가 한 방향으로 감소하는 수조도
통과시킬 수 있었다. 한 가지 풀스톡 배치만 검사해도 지급된 기초 균막만
사용하는 보통 플레이를 놓친다. 따라서 아래 개체·화면 단위 회귀는 유지하되,
생태계 배포 판정은 서로 다른 두 `7,200초` 시나리오를 같은 기준으로 검사한다.

| 범위 | 확인 결과 |
|---|---|
| 물벼룩 개체 모델 | 화면 한 마리와 계산 개체 한 마리가 1:1로 대응하고 식별자·위치·나이·수명·세대를 개별 추적 |
| 물질 규모 | 한 번 배치하면 게임 물질 `0.010575`인 성체 한 마리. 지급 체리새우 `1.08`의 약 `1/102`; 실제 건중량/습중량의 정밀 환산값은 아님 |
| 여과·번식 | 유생·성체에 같은 `M^0.75` 연속 체질량 여과 곡선을 적용하고, 모체가 실제로 먹어 유지비를 넘긴 고품질 먹이와 보존된 번식 질량만 출생에 사용 |
| 국소 이동 | 먹이 방향 레이더 없이 상관 배회·흐름으로 이동하고, 산소·독성 회피만 반경 `42`의 인접 8방향을 사용 |
| 압축 생애 | 수명 `750~1,550초`, 출산 휴지기 `220초`와 포란 발생 `40초`; 체리새우보다 짧은 상대 관계 유지 |
| 옛 `4,800초` 지급 구성 | 물벼룩 `3→4마리`, 최대 `6마리`, 최고 `8세대`; 최종 생존만 확인했으므로 장기 배포 근거에서는 제외 |
| 부유 색 지도 | 첫 부유층은 연속 색면, 추가 부유층은 등치선·국소 지점; 식물플랑크톤 `12`, 부유 분해균 `8` 절대 스케일 |
| 관찰 기록 | 다섯 그래프 묶음을 독립적으로 접고 펼침; `수조 전체` 고정 중 선택 스냅샷이 탭·스크롤을 바꾸지 않음 |
| 카메라 | 맞춤 보기보다 `28%` 추가 축소, cover 기준 `50%` 하한과 패널 회피용 제한 이동 |
| 새우 섭식 | 조류·균 필름 공존 시 조류가 요청량의 최소 `72%`; 실제 조류 감소분만 누적하고 세부 무늬도 생체량에 맞춰 갱신 |

미션 7 장주기는 다음 명령으로 두 고정 fixture를 차례로 재현한다. 모델 수치
보정 중에는 `verify:mission-7-long-run:minimal`과
`verify:mission-7-long-run:full-stock`을 따로 실행해 어느 조건에서
실패했는지 분리한다.

```text
npm run verify:mission-7-matrix
```

두 fixture는 다음과 같다.

| fixture | 배치 | 놓치면 안 되는 문제 |
|---|---|---|
| `starter-only-minimal` | 길든 바닥재의 기초 균막, 식물플랑크톤·물벼룩 각 3개체, 새우 4마리, 나사말 3포기, 부착조류 각 1회. 추가 균 접종 없음 | 사용자가 분해균·질산화균을 다시 놓지 않았다는 이유만으로 나사말과 전체 순환이 무너지는 숨은 정답 |
| `full-stock-stress` | 식물플랑크톤·물벼룩 각 3개체, 새우 4마리, 나사말 3포기, 부착조류 각 4회, 두 균 기능군 각 2회 | 지급 자원을 많이 배치했을 때 생물 부하와 분해 부하가 커져 무너지는 문제 |

두 시나리오는 모두 `7,200초`를 실행하고 후반 `3,600초`를 따로 판정한다.
최소 배치에만 느슨한 합격선을 주지 않는다.

- 물벼룩은 한 번 놓을 때 실제 한 개체만 생긴다. 자연번식 뒤 후반 최소
  `20마리`, 평균 `30마리` 이상과 후반 출생·성숙,
  창시자 교체, 살아 있는 2세대 이상 자손을 확인한다.
- `1,000마리`는 게임 상한이나 번식 제한이 아니라 2시간 안의 비정상
  폭증을 잡는 검증 경보다. 정상 계산에는 개체 수 하드 캡을 두지 않는다.
- 체리새우 후반 출생·성숙, 살아 있는 출생 자손, 성체 암수, 사망 원인
- 식물플랑크톤 바닥값뿐 아니라 의미 있는 고갈 뒤 회복
- 지급 나사말 소멸 뒤 러너의 러너까지 이어진 세대, 후반 생존과 최종 생체량
- 두 균 군집, 산소·독성 노폐물·유기물 안전 범위
- `120초` 표본 전체의 질소·탄소·산소 등가 최대 장부 오차

이 항목 중 하나라도 실패하면 화면상 미션 성공 여부와 무관하게 미션 7의
장기 먹이망은 미통과다. 이 밀도 검사는 물벼룩 자체의 장기 유지 조건이지
송사리 먹이 부하를 검증한 결과가 아니다. 큰 수조에서 송사리가 실제로
물벼룩을 포식하는 별도 부하 시험을 통과하기 전에는 `송사리 준비 완료`로
표시하지 않는다.

> **현재 결과:** 보정된 공통 물벼룩 상수로 `starter-only-minimal`은
> 후반 `57~154마리`(평균 `123.10`), `full-stock-stress`는
> `50~124마리`(평균 `91.16`)로 모든 `7,200초` 조건을 통과했다.
> 전체 지급 `14,400초` 확장 실행도 `50~125마리`(평균 `83.22`,
> 최종 `90`)와 식물플랑크톤 `5.67~17.32`를 유지했다. 미션 7 장기
> 게이트는 **통과**, 미션 8 송사리 포식 부하 게이트는 **미검증**이다.
> 옛 `4,800초` 생존 기록이나 화면의
> 단기 미션 성공을 이 판정으로 대체하지 않는다.

| 진단 | 결과 | 판정 |
|---|---|---|
| 송사리의 어린 새우 포식을 낮춤 | 새우는 남지만 송사리가 약 `3,000초` 전후 굶어 사라짐 | 송사리 먹이 기반 부족 |
| 어린 새우 포식을 높임 | 일부 배치에서 새우 파동이 커진 뒤 산소 부족과 연쇄 붕괴 | 작은 수조의 강한 직접 결합 |
| 부착조류 보조식을 높임 | 송사리와 체리새우의 역할이 겹치고 기존 조류 균형에 개입 | 생태 역할 분리 실패 |

따라서 `치어 1마리 부화`는 장기 먹이망 성공의 충분조건이 아니다. 미션 7은
식물플랑크톤과 물벼룩의 세대 연결로 개편하고, 송사리는 큰 수조와 물벼룩을
갖춘 다음 미션에서 다시 검증한다. 상세 내용은
[미션 07–08 상세 명세](./content/MISSIONS_07_08_PLANKTON_RICEFISH.md)를 따른다.

세부 과학적·수치적 근거는
[생태·수질·열수송 모델](./04_SIMULATION_MODEL.md), 장주기 물질 장부
수식과 기준은 [화학량론 장부 구현 기록](./06_STOICHIOMETRIC_LEDGER.md)을
따른다.

미션 2·3·5·6의 최종 성공 판정과 장주기 생존은 위 수동 확인에서 같은 계산을
반복하지 않고 전체 자동 회귀와 50주기 확장 검증 결과를 사용했다. 수동 확인은
지급 제한, 배치·선택·카메라·관찰·저장처럼 화면에서만 확인할 수 있는 계약에
집중했다. 이번 확인에서 새로 재현된 화면 파손, 흰 화면, 테두리 소실 또는
조작 불능 문제는 없었다.

기본 5초 제한으로 실행되던 두 상태 검사는 전체 장주기 회귀 직후 CPU 상태에
따라 거짓 시간 초과가 발생했다. 두 검사는 벽시계 성능을 판정하지 않고
`빠른 실행 뒤에도 모션 스냅샷이 순서·개체 수를 보존하는지`, `실제 광량장이
유한한 수온 구배를 만드는지`를 판정한다. 따라서 생태·수치 합격식은 바꾸지
않고 시험별 안전 시간을 15초로 명시했다. 실제 64배속 성능 계약은 별도의
미션 4·5 30분 장기 검사에서 계속 측정한다.

미션 4의 30분 자동 회귀는 평평한 바닥만 쓰지 않고 넓적한 돌과 세로 돌을 함께
배치하고, 바닥·돌 표면에 두 조류를 분산 접종한 뒤 성체 4마리로 시작한다.
출생이 실제로 발생하고 종료 시 생존 개체가 남아 있어야 하며, 실행 중 새우
최고 개체 수는 30마리 이하, 생산자 최고 총량은 65 이하이어야 한다. 별도
무조류 회귀에서는 초기 성체의 저장량만으로 120초 유지 목표를 통과하지 못하고
성체 수가 먼저 감소하는지 확인한다. 이 경계는 미션 전용 새우 상한이 아니라
단순 영양 저장고와 기존 공통 생애주기가 함께 만든 결과를 감시한다.
