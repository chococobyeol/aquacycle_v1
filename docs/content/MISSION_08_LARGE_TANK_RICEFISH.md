# 미션 08 상세 명세 — 긴 수조의 송사리

> 문서 상태: 플레이어블 미션 8 프로토타입 구현 · 장기 먹이망 재검증 중 · 완료 조건 미결정
> 작성일: 2026-07-28
> 관련 문서: [미션 7 상세 명세](./MISSION_07_PLANKTON_DAPHNIA.md) · [콘텐츠 로드맵](../07_CONTENT_ROADMAP.md) · [게임 기획](../01_GAME_DESIGN.md) · [시뮬레이션 모델](../04_SIMULATION_MODEL.md)

미션 8부터 긴 대형 수조를 사용하고, 미션 7에서 검증한 식물플랑크톤과
물벼룩 먹이망에 송사리를 다시 연결한다. 플레이 시작부터 포식자를 함께
넣지 않고, 식물플랑크톤을 먹는 물벼룩 군집이 먼저 번식한 뒤 일시정지해
송사리를 직접 방류하는 순서를 기준으로 삼는다. 게임은 이 과정을 안내만
하며 물벼룩 자동 보충, 개체 수 강제 하한과 송사리 자동 방류를 사용하지
않는다. 현재 임시 송사리 행동의 감지
거리나 포획률에 수조 크기를 맞추지 않는다. 먼저 생물의 실제 화면 크기와
공간 밀도를 유지하는 수조, 사용자가 만든 피난처와 접근 가능한 먹이망을
구현한 뒤 송사리 행동과 생태 균형을 다시 보정한다.

---

## 1. 결정 상태

### 합의됨

- 미션 8부터 가로가 긴 대형 수조를 사용한다.
- 실험실 내부에서 수조 종류를 선택하고 마지막 선택을 기억한다.
- 작은 돌과 기존 돌의 실제 배치로 새우 피난처를 만들 수 있게 한다.
- 돌 표면 조류 섭식과 돌 틈 피난을 함께 유지한다.
- 큰 생물도 틈과 같은 화면 좌표의 앞쪽 물속을 지나갈 수 있다.
- 몸집 제한은 화면 좌표가 아니라 틈 내부로 들어가는 입구에 적용한다.
- 현재 송사리 그림과 리깅은 최종 자산으로 사용하지 않고 전면 재제작한다.
- 첫 구현은 작은 납작돌 `104×47`, 작은 쐐기돌 `112×64` 두 종류를 쓴다.
- 실험실에서 수조 종류를 바꾸면 현재 배치를 초기화하며 마지막 선택을 기억한다.
- 위험 단서장은 물 격자와 같은 크기의 배열 하나만 사용하고 저장·복원한다.
- 실험실에서 공간 판정 표시를 켜 돌 외곽, 부착면, 틈 폭과 생물 몸 두께를
  실제 수조 위에 겹쳐 볼 수 있다.
- 미션 목록에 `실험 8`을 등록하고 긴 수조로 바로 진입하는 플레이어블
  시나리오를 제공한다.
- 식물플랑크톤과 물벼룩을 먼저 운영해 물벼룩이 번식하면 일시정지하고,
  보유 중인 송사리를 그때 방류한다.
- 물벼룩 총수·후손 성체·세대 진행을 바탕으로 한 화면 준비도는 방류 시점
  선택을 돕는 권고다. 송사리 배치를 잠그는 완료 조건으로 사용하지 않는다.
- 게임 계산에는 물벼룩 자동 보충, 개체 수 강제 하한과 송사리 자동 방류를
  두지 않는다.
- 송사리는 큰물벼룩을 주 먹이로 포식하고 몸집에 맞는 어린 체리새우만
  보조 먹이로 이용한다. 조류와 생물막은 직접 먹지 않는다.
- 완료 조건을 합의하기 전까지 성공·실패와 제한시간은 적용하지 않는다.
- 프로토타입에서는 피난 구조를 자유롭게 시험할 수 있도록 기존 돌과 작은
  돌을 무제한 지급한다. 최종 미션의 제한 수량은 아직 확정하지 않는다.

### 미결정

- 미션 8의 최종 이름과 완료 조건
- 미션 8에서 지급할 작은 돌의 종류별 수량
- 첫 구현의 틈 여유 폭·몸 두께 계수를 생태 결과에 맞춰 조정할지 여부
- 송사리의 최종 감지·추격·포획 수치
- 개발용 공간 판정 시각화의 일반 플레이 노출 여부

## 2. 수조 종류와 적용 범위

- 미션 1–7은 현재 표준 수조를 유지한다.
- 미션 8은 긴 대형 수조를 사용한다.
- 실험실에 들어가기 전 별도 선택 화면을 띄우지 않는다.
- 실험실 내부 설정에 `표준 수조`와 `긴 대형 수조` 선택을 둔다.
- 마지막으로 선택한 수조 종류를 저장하고, 다음에 실험실에 들어오면
  별도 확인 없이 그 수조를 바로 연다.
- 처음 실험실을 사용하는 경우에만 표준 수조를 기본값으로 사용한다.
- 실행 중에는 수조 종류 버튼을 잠근다. 준비 또는 일시정지 상태에서
  수조 종류를 바꾸면 현재 실험과 배치를 초기화하고 새 수조 정의를 적용한다.
- 미션은 각 시나리오가 수조 종류를 정하므로 선택 UI를 표시하지 않는다.
- 표준·긴 대형 수조 이후의 추가 수조 종류는 후속 논의로 남긴다.

## 3. 수조 크기와 환경 셀

### 3.1 첫 구현 기준

| 항목 | 표준 수조 | 긴 대형 수조 |
|---|---:|---:|
| 세계 크기 | `1200×720` | `2400×720` |
| 상대 크기 | 기준 | 가로·면적 `2배`, 세로 동일 |
| 물·수질 격자 | `36×20` | `72×20` |
| 총 셀 수 | `720` | `1440` |

대형 수조는 현재 수심을 유지하고 가로만 두 배로 늘린다. 송사리의 유영
거리와 피식자의 분산·피난 공간 효과를 먼저 검증하고, 기존 수심의 광량,
수온과 생물의 수직 분포는 이번 확장에서 바꾸지 않는다. 격자도 열만
두 배로 늘려 현재 셀의 물리적 크기와 공간 해상도를 유지한다. 수조만
커지고 격자가 성기게 되어 국소 농도·수온·흐름·식물플랑크톤 구름이
뭉개지는 방식은 사용하지 않는다.

### 3.2 확대하지 않는 값

생물, 구조물, 표면 생태 셀과 감지 거리의 논리 크기는 수조와 함께 확대하지
않는다.

| 대상 | 현재 표준 수조의 논리 크기 |
|---|---:|
| 넓적한 사암 | `290×85` |
| 둥근 강돌 | `180×117` |
| 세로 판석 | `118×255` |
| 표면 생태 셀 | 약 `9` |
| 어린 체리새우 몸길이 | `14` |
| 성체 체리새우 몸길이 | `36` |
| 성체 송사리 몸길이 | `44` |

이 상대 크기를 유지한 채 실제 이동·먹이·피난 공간을 늘린다. 현재 임시
송사리의 수치에 맞추기 위해 생물이나 구조물을 함께 키우지 않는다.

`2400×720 / 72×20`은 첫 프로토타입과 성능 검증에 사용할 기준값이다.
최종 수치는 장주기 생태 결과와 실제 화면 구도를 확인한 뒤 조정할 수 있지만,
조정할 때도 표준 수조보다 셀 밀도를 낮추지 않는다.

### 3.3 세로 확장 보류

화면 세로 방향의 수심과 환경장 행 수는 미션 8에서 늘리지 않는다. 이후
다음과 같은 콘텐츠가 실제로 필요할 때 별도 설계한다.

- 수면·중층·바닥에서 서로 다른 생물 분포와 계절 이동
- 수심에 따른 광량·수온·산소 성층을 더 세밀하게 관찰하는 콘텐츠
- 바닥 높이, 경사, 웅덩이와 단차처럼 수조 내부 지형이 달라지는 기능
- 더 깊은 수조 자체가 플레이의 선택이 되는 추가 수조 종류

이때는 세계 높이, 물·수질 격자의 행 수, 바닥 경계와 카메라 구도를 함께
검토한다. 돌 틈의 통과 가능 판정은 화면 세로 수심과 다른 국소 접근
정보이므로 이번 결정과 충돌하지 않는다.

### 3.4 물질·에너지의 자동 비례

수조 크기에 따라 기하학적으로 정해지는 값은 사용자에게 별도 설정을
요구하지 않고 수조 정의에서 자동으로 계산한다.

- 긴 수조도 각 물 셀의 크기와 초기 농도는 표준 수조와 같다.
- 가로 셀 수가 두 배이므로 같은 초기 농도에서 물속 총 산소·영양염·유기물,
  독성 노폐물·무기탄소와 열용량은 자동으로 두 배가 된다.
- 수면 길이, 바닥 면적과 닫힌 공기층 용량도 두 배가 되므로 전체 기체
  교환량, 바닥 저장량과 공기 저장량은 같은 단위 면적 규칙에서 두 배가 된다.
- 자연광은 단위 면적당 입사량을 표준 수조와 같게 둔다. 광량 수치를
  인위적으로 두 배로 올리지 않고, 두 배로 넓어진 수면과 셀에 같은
  입사량을 적용해 전체 유입 에너지가 자연스럽게 두 배가 되게 한다.
- 수온의 초기값과 단위 면적당 외부 열교환 조건도 같게 둔다. 총 열용량과
  전체 경계 교환량은 수조 크기에서 계산한다.
- 식물플랑크톤 같은 배경 농도를 초기화할 때는 같은 농도를 전체 셀에
  적용한다. 반면 개별 생물, 돌, 수초와 한 번의 접종량은 수조가 커졌다는
  이유만으로 자동 복제하거나 두 배로 키우지 않는다.
- 자연광과 달리 특정 위치의 전등·장치는 국소 광원이다. 긴 수조 전체를
  자동으로 같은 밝기로 만들지 않고 실제 위치·범위에서 계산한다.

이 원칙은 큰 수조 전용 보정 상수를 만드는 것이 아니라, 농도·단위 면적
플럭스·셀 부피를 같은 규칙으로 두고 수조의 셀 수와 경계 길이가 결과를
결정하게 하는 방식이다.

### 3.5 카메라와 줌

- 사용자는 표준·긴 수조 모두에서 줌과 화면 이동을 자유롭게 조절한다.
- 긴 수조의 기본 시작 배율은 생물과 구조물이 현재 표준 수조와 같은
  화면 크기로 보이는 배율이다.
- `맞춤 보기`는 긴 수조 전체가 한 화면에 들어오도록 축소한다.
- 맞춤 보기 이후에도 사용자가 원하는 배율로 다시 확대·축소할 수 있다.

## 4. 작은 돌과 사용자 제작 피난처

- 작은 돌을 완성형 구조물 종류로 추가한다.
- 작은 돌 하나에 `은신처` 보너스를 직접 붙이지 않는다.
- 사용자가 작은 돌과 기존 돌을 쌓거나 기대어 만든 실제 빈 공간에서
  피난처가 생겨야 한다.
- 기존 돌의 단순한 절반 축소판이 아니라 납작한 돌과 쐐기형 돌을 각각
  별도 외곽선·그림으로 구현한다.
- 첫 구현 크기는 작은 납작돌 `104×47`, 작은 쐐기돌 `112×64`다.
- 두 돌 모두 기존 돌처럼 같은 원본 형상에서 배치 충돌 외곽선과 부착
  생태 표면을 만들며, 실험실에서는 무제한으로 쓸 수 있다.
- 미션 1–7의 구조물 목록과 지급량에는 추가하지 않는다. 미션 8 지급량은
  완료 조건과 공간 난이도를 정할 때 함께 확정한다.

## 5. 돌 데이터의 역할 분리

돌마다 서로 무관한 상태를 여러 벌 저장하지 않는다. 하나의 원본 형상과
로컬 좌표에서 다음 표현을 파생한다.

```text
돌의 원본 형상
├─ 구조물 배치 물리·접촉·시야 차단에 쓰는 외곽선
├─ 부착조류와 균막이 자라는 표면 생태 셀
└─ 모든 돌의 배치를 합쳐 계산한 몸집별 틈새 연결망
```

세 번째 항목은 개별 돌에 붙는 `은신처 레이어`가 아니다. 안착한 모든 돌,
바닥과 필요한 구조의 배치를 함께 보고 만들어지는 수조 단위의 파생
자료다. 통로에는 통과 가능한 최소 여유 폭을 기록하고, 실제 이용 가능
여부는 종 이름이 아니라 각 개체의 현재 몸 크기와 자세에서 계산한다.
성능을 위해 몇 개의 여유 폭 구간을 캐시할 수는 있지만 `새우용`,
`송사리 금지`처럼 종별 통로를 따로 만들지 않는다.

돌의 화면 실루엣 전체를 자유 유영 생물의 막힌 벽으로 사용하지 않는다.
측면 2D 화면의 같은 좌표에서도 생물이 돌 앞을 지나갈 수 있기 때문이다.
구조물 외곽선은 돌끼리의 배치 물리, 표면 위치, 입구 폭과 실제 시야
차단이 생기는 경우를 계산하는 근거로 사용한다.

## 6. 앞쪽 물속·표면·보이는 틈 경로

생물은 하나의 개체와 하나의 2D 위치를 유지한다. 별도 개체를 만들거나
긴 행동 상태 목록을 추가하지 않고, 현재 위치가 열린 물속·표면·몸집이
제한되는 틈 중 어디에 해당하는지만 이동 판정에 사용한다.

| 경로 구간 | 의미 | 접근 |
|---|---|---|
| `openWater` | 돌보다 앞쪽의 열린 물속 | 자유 유영 생물 모두 |
| `surface` | 돌의 보이는 앞면을 기어가는 표면 | 표면 섭식이 가능한 생물 |
| `crevice` | 화면에 보이는 돌 사이의 좁은 빈 공간 | 입구 여유 폭에 맞는 생물만 |

큰 새우나 송사리도 틈과 같은 화면 좌표로 이동할 수 있다. 이때는
`openWater` 경로에서 돌 앞을 지나간다. 몸집이 맞는 작은 새우는 실제
입구를 통해 `crevice`로 판정되는 빈 공간을 이용한다.

따라서 몸집 판정은 화면 좌표를 막는 보이지 않는 벽이 아니라 **틈 내부로
연결되는 입구의 사용 가능 여부**에만 적용한다.

```text
앞쪽 물속 ↔ 노출된 표면 경계 ↔ 돌 표면
     └──── 실제 틈 입구 ──── 틈 내부
```

경로 전환은 실제 연결점에서만 일어난다. 표면 조류를 목표로 한 새우는
기존 표면 생태 셀까지 이동할 수 있다. 새우가 기어가는 돌 앞면을 일반
고체 벽으로 막지 않으므로 구조물 충돌 때문에 조류를 먹지 못하는 문제가
생기지 않는다.

`crevice`는 렌더링 깊이나 숨김 상태가 아니다. 틈에 들어간 새우도 다른
새우와 똑같은 밝기·크기·투명도로 계속 화면에 표시한다. 돌 사이의 실제
빈 공간에 있으므로 인위적으로 돌 뒤로 보내거나 흐리게 만들지 않는다.
돌 그림 자체가 몸 일부와 겹치는 경우에만 기존 2D 그리기 순서에서 생기는
자연스러운 겹침을 허용한다.

## 7. 피난과 포식 판정

### 7.1 포식자 감지

새우가 모든 송사리의 좌표를 읽거나 수조 전체를 검색하지 않는다. 다음
국소 단서를 조합한다.

- `위험 단서장`은 물 격자당 실수 하나만 추가하는 비물질성 행동장이다.
  송사리는 약한 배경 소스를 내고, 새우가 실제 공격받거나 포식되면 같은
  장에 더 강한 국소 펄스를 더한다. 물 흐름을 따라 이동·확산하고 계속
  감소하므로 영구 누적되지 않는다.
- 위험 단서장만 감지한 새우는 주변 위험 가능성만 알고 경계 수준을
  높인다. 이 값은 송사리의 정확한 좌표나 식별자를 알려 주지 않으며,
  냄새만으로 특정 틈을 바로 선택하지 않는다.
- 가까운 개체는 기존 공간 구역에서만 조회한다. 현재 새우를 실제로
  포식할 수 있는 몸 크기·생애 단계의 송사리가 감지 범위에 들어오면
  거리, 상대속도, 접근 방향과 실제 시야를 순서대로 확인한다.
- 아주 가까운 송사리의 빠른 접근·공격은 별도의 유체 진동장을 만들지
  않고 짧은 국소 위험 이벤트로 전달한다. 이는 꼬리치기 같은 즉시 도주를
  시작시키는 근접 단서다.
- 배경 위험 단서만 있으면 조심스러운 기존 이동을 유지하고, 포식 가능한
  송사리의 직접 접근이나 강한 국소 이벤트가 있을 때만 방향성 도주와
  틈 후보 조사를 시작한다.

첫 구현은 가까운 송사리 후보를 최대 `220` 거리 안에서 조회하고, 먼 후보는
실제로 접근 중일 때만 시야선을 검사한다. 위험 단서장의 반감기는 약
`14초`이며, 송사리의 약한 배경 소스와 공격 시 강한 펄스가 같은 배열에
들어간다. 이 값들은 전수 비교와 영구 누적을 피하는 구현 기준이며 미션 8
생태 난이도의 최종 수치는 아니다.

```text
위험 단서 없음
→ 기존 탐색·섭식·휴식

위험 단서장만 감지
→ 경계 수준만 상승, 포식자 위치는 모름

포식 가능한 송사리의 직접 접근
→ 반대 방향 도주, 가까운 틈 후보 확인

피식자만 통과 가능한 틈
→ 실제 입구를 통해 피난
```

### 7.2 피난 동기와 접근 판정

- **통과 가능 여부와 틈을 찾는 동기는 분리한다.** 몸이 맞는 성체 새우도
  틈을 통과하고 그 안에 머물 수 있지만, 틈이라는 이유만으로 평상시
  목표로 선택하지 않는다.
- 천적이 없는 미션 1–7에서는 기존 탐색·표면 섭식·휴식 행동을 그대로
  유지한다. 새우가 먹이를 따라 우연히 틈을 지나거나 그 위치에서 기존
  휴식 타이머가 시작될 수는 있지만 `휴식처 찾기` 이동을 새로 추가하지
  않는다.
- 피난 경로 탐색은 현재 개체를 실제로 포식할 수 있는 포식자를 감지했을
  때만 시작한다. 미션 번호나 송사리 존재 자체가 아니라 현재 포식 가능
  관계와 국소 위협을 조건으로 사용한다.
- 현재 송사리의 먹이 크기 범위 밖인 성체 새우는 송사리가 가깝다는
  이유만으로 틈을 찾아 숨지 않는다. 이후 성체 새우를 먹는 다른 천적이
  추가되면 같은 일반 위협 판정으로 피난 행동이 활성화될 수 있다.
- 위협받은 새우는 가까운 틈 입구 후보만 조사한다.
- 후보는 새우에게 연결되어 있고, 현재 송사리의 몸집으로는 내부에
  도달하거나 입을 넣어 물 수 없을 때 피난처가 된다.
- `돌 근처`, `작은 돌 보유` 같은 숨은 보너스만으로 포획률을 낮추지 않는다.
- 적합한 틈이 없으면 새우는 송사리 반대 방향과 주변 열린 경로를 따라
  도망친다.
- 같은 화면 좌표에 송사리와 새우가 있어도 새우가 `crevice`, 송사리가
  `openWater`에 있고 입구를 통과할 수 없다면 공격은 성립하지 않는다.
- 송사리는 돌 앞을 자유롭게 유영할 수 있지만 몸집이 맞지 않는 틈 내부로
  바로 전환하거나 그 안의 먹이를 공격할 수 없다.
- 치어나 어린 송사리처럼 현재 몸이 작아 입구 여유 폭에 맞는 개체는
  같은 틈에 들어갈 수 있다. 그 송사리가 해당 먹이를 포식할 수 있는
  생애 단계라면 틈 안에서도 일반적인 추적·포식 규칙을 적용한다.
- 송사리가 틈 속 새우를 화면에서 볼 수 있어도 물리적으로 닿지 않으면
  포식할 수 없다. 돌이 실제 시야까지 가리는 배치에서는 추적을 잃는
  효과가 추가되지만, 시야 차단은 피난처 성립의 필수 조건이 아니다.
- 물벼룩은 새우처럼 돌 표면을 기거나 의도적으로 좁은 돌 틈을 찾아가는
  행동을 사용하지 않는다. 물 흐름과 국소 먹이, 포식자 단서에 반응하며
  낮에는 주변 나사말 수관이 실제 시각 포식 위험을 낮추는 방향이면 그
  국소 위험 경사를 따라 이동할 수 있다.

따라서 `피난처`는 공간에 고정된 속성이 아니다. **도망가는 개체는 통과할
수 있지만 현재 추격자는 통과하거나 입을 뻗어 닿을 수 없는가**를 두
개체의 현재 크기로 비교한 순간적인 관계다. 같은 틈도 성체 송사리에게는
새우 피난처가 될 수 있고 더 작은 송사리에게는 아닐 수 있다.

### 7.3 물벼룩의 나사말 차폐

나사말을 물벼룩의 고정 안전지대로 지정하지 않는다. 실험에서는 포식자가
수초 밖에서 사냥할 때 수초가 피난처가 되지만, 작은 시각 포식자가 수초
안으로 들어와 사냥하면 물벼룩이 수초를 피하는 반대 결과도 나타난다.
따라서 현재 구현은 다음처럼 **포식자에 상대적인 국소 시각 위험**을 쓴다.

- 가까이 접근 중인 송사리는 낮과 밤 모두 직접 감지해 반대 방향으로
  도주한다.
- 넓게 퍼진 위험 단서만 있을 때는 낮에만 현재 위치 주변 `34` 거리의
  네 방향을 조사한다.
- 각 조사점의 위험은 `국소 위험 단서 × 나사말 밖 시각 노출`로 계산하고,
  물벼룩은 더 낮은 국소 위험 방향으로 움직인다.
- 위험 단서가 없거나 수초가 조사 범위 밖이면 수초 위치를 찾아가지 않는다.
- 밤에는 확산 단서만으로 방향성 이동을 만들지 않지만, 실제 접근한
  송사리에 대한 직접 도주는 유지한다.
- 송사리가 수초 밖에 있고 먹이가 수관 안에 있으면 차폐 이득이 크다.
  송사리도 같은 수관에 들어오면 이득은 줄지만, 두 개체 사이에 남을 수
  있는 잎까지 0으로 만들어 투시 능력을 주지는 않는다.

나사말 차폐는 포획 면역이 아니다. 송사리의 국소 발견률과 공격 성공률을
연속적으로 낮출 뿐이며, 실제 돌 틈처럼 접근을 물리적으로 차단하지 않는다.
수관 외곽과 구조 크기는 광량 계산에서 이미 만든 나사말 기하 캐시를
재사용하고 `96` 단위 공간 구역에 넣어, 물벼룩마다 잎 곡선을 다시 만들거나
수조 전체 나사말을 훑지 않는다.

### 7.4 나사말 잎의 산소 생산과 호흡

나사말 광량은 화면에 그린 각 잎의 여러 높이에서 표본을 얻어 계산한다.
낮 광합성으로 생긴 산소도 영양분을 흡수한 뿌리 셀 한 곳에 몰아넣지 않고,
각 잎 표본의 실제 총광합성률 비율대로 잎 전체의 물 셀에 나눠 방출한다.
무기탄소·질소 흡수 위치와 산소 방출 위치는 분리하되, 생산한 생체량과
산소 총량은 기존 닫힌 물질 장부와 정확히 같아야 한다.

밤 호흡 역시 영양분 흡수에 유리했던 한 점에서 전체 산소를 소비하지 않고
잎 면적을 따라 분산한다. 따라서 긴 잎을 가진 한 포기가 바닥의 작은
부착조류와 같은 산소 공간원으로 취급되지 않으며, 산란된 알의 국소 수질도
실제 잎 주변 생산·호흡과 물 수송의 결과를 받는다.

나사말에 붙인 송사리 알의 저장 소유권은 기존처럼 뿌리의 표면 셀 ID를
사용하지만, 실제 위치는 바닥 셀 중심이 아니라 그 포기에 그려진 잎 중간
지점이다. 산란 전 수질 검사와 부화 전 국소 산소·독성 판정도 이 잎 좌표를
사용한다.

## 8. 먹이 관계와 방류 순서

이 절은 먹이망의 방향만 기록하며 정확한 비율과 포획률은 확정하지 않는다.

| 먹이 | 송사리에서의 역할 |
|---|---|
| 물벼룩 | 주 동물성 먹이 |
| 몸집에 맞는 어린 체리새우 | 국소적으로 만날 때 포식하는 보조 먹이 |
| 식물플랑크톤 | 송사리가 직접 먹지 않으며 물벼룩을 키우는 생산자 |
| 부착 조류·생물막 | 송사리의 섭식 대상이 아님 |
| 나사말 | 먹이가 아니라 산란·차폐 구조 |

송사리는 물벼룩의 실제 구조량과 자신의 생애 단계에 맞는 개체를 골라
추적한다. 화면의 `어린 개체/성체` 이름만으로 먹이 가능 여부가 갑자기
바뀌지 않으며, 같은 원칙으로 실제 구조량이 충분히 작은 어린 체리새우만
보조 먹이가 된다.
어린 체리새우 포식은 물벼룩이 부족할 때 조류로 대체하는 생존 보정이
아니라, 실제로 닿고 삼킬 수 있는 개체를 만났을 때만 성립하는 보조 경로다.
정확한 포획률과 섭식량은 큰 수조의 새 공간 구조에서 다시 보정한다.

먹이 수가 적으면 실제 후보를 만날 횟수가 자연스럽게 줄지만, 이미 가까운
밝은 곳에서 시야와 접근 가능성이 확보된 한 개체의 인식률을 개체군 총수로
다시 낮추지 않는다. 물벼룩과 먹을 수 있는 어린 새우를 동시에 발견하면
종 이름의 고정 우선순위가 아니라 거리·노출·먹이 크기·획득량을 비교한다.
추적 중에도 입 가까이 더 좋은 먹이가 들어오면 표적을 바꾸되, 비슷한
두 후보 사이에서 매 프레임 흔들리지 않도록 최소 거리·점수 차이를 둔다.

추격 도착점과 포획 접촉은 송사리의 몸 중심이 아니라 화면에 그려진 입
위치를 기준으로 한다. 송사리 중심이 먹이 중심을 통과하도록 유도하지
않고, 입이 먹이에 닿는 중심 오프셋을 유지하며 움직이는 먹이의 속도를
따라간다. 위아래 먹이도 옆모습 그림이 실제로 낼 수 있는 몸 기울기 안에서
측면으로 돌아 접근해, 보이지 않는 수직 입 방향을 추격점으로 쓰지 않는다.
실제 입 접촉 뒤 놓친 경우에는 짧은 공격 회복 뒤 한 번 더
시도한다. 이미 입에 닿은 먹이를 여러 초 동안 물지 못한 채 밀고 다니는
상태는 허용하지 않는다. 나사말 차폐, 어두운 광량과 상대적 돌 틈 접근
불가는 이 근접 판정에서도 그대로 유지한다.

송사리는 성공적으로 먹은 뒤에도 성장·번식에 필요한 물질이 아직 부족할
수 있지만, 그 이유로 위 내용물이 남은 동안 곧바로 다음 먹이를 공격하지
않는다. 포식 질량은 기존 보존 장부에 한 번만 들어가고, 같은 양을
`recentIntake`에 비물질성 위 내용물 신호로 기록한다. 위 용량은 현재
구조량에 비례하며, 신호가 소화로 절반 이하가 될 때까지 새 먹이 표적을
찾지 않는다. 이 상태는 먹이나 에너지를 추가하는 저장고가 아니고
연속 포획만 잠시 억제하는 행동 상태다.

모든 생애 단계는 유지비와 체급 비례 비축분을 먼저 지불한다. 치어와 어린
개체는 남은 순잉여를 성장에 쓰고, 성체 암컷은 같은 순잉여에서 실제 알
질량을 먼저 번식 저장량으로 옮긴 뒤 남은 양만 성장에 쓴다. 수컷은
구애·추적 활동 대사로 번식 비용을 낸다. 따라서 송사리 이상성 성장 모델의
성숙 전후 차이를 따르되, 먹이 한 끼에 임의의 고정 성장 분율을 붙이거나
나이만으로 구조 질량을 추가하지 않는다.

성체 체성장은 성숙 크기에서 최대 크기까지의 진행률을 `p`로 두고 성장
속도 상한을 `(1 - p)^2`로 감속한다. 진행률 `0/20/50/80%`에서 상대
상한은 각각 `100/64/25/4%`다. 성장용 비축 하한도 포만 상태 점수
`0.568`을 남기도록 설정해 사냥 종료선 `0.56`보다 낮아지지 않는다.
이 제한은 치어·유어의 먹이로 지불한 성장을 바꾸지 않고, 아직 최대 크기가
아닌 성체가 성장 때문에 계속 사냥 상태에 남는 경로만 막는다.

현재 압축 시간에서 위 내용물 신호의 반감기는 `90초`다. 이는 물벼룩이
적다는 전역 개체 수를 송사리가 아는 보정이 아니라, 이미 잡아먹은 한
끼를 처리하는 동안 다음 사냥을 멈추는 개체별 처리 시간이다. 따라서
눈앞의 먹이 인식·입 접촉 포획은 유지하면서 먹이가 많을 때 포식량이
무한히 선형 증가하지 않는 포화형 기능반응을 만든다.

성체 암컷의 번식 사냥은 화면용 에너지 수치가 아니라, 이미 보존된 번식
저장량과 성체 유지분을 제외하고 알로 옮길 수 있는 저장량의 합으로
판정한다. 그 합이 한 육방의 알 질량보다 작을 때만 먹이를 계속 찾고, 실제
물질이 충분해지면 사냥을 멈춘다. 산란 후 대기 중에는 다음 육방을 미리
채우지 않으며, 알마다 전체 출생 질량을 어미의 보존량에서 차감한다.

한 번의 실제 산란에서 관찰되는 약 8–48개 알은 화면 개체 3마리로 압축한다.
기존 2마리는 암수 한 쌍이 자기 자신만 겨우 대체하는 값이라, 먹이가 충분한
조건에서도 한 형제의 평범한 성장 지연만으로 성숙한 짝이 사라지고 계통이
끝났다. 3마리 육방은 양쪽 성을 포함하면서 한 개체의 성장 편차를 견디는
최소 표현이다. 세 알은 모두 어미가 섭식해 보존한 물질에서 각각 차감하므로
저밀도 자동 보충이나 무상 개체 생성은 아니다.

### 8.1 기준 플레이 순서

1. 준비 단계에서 식물플랑크톤과 큰물벼룩을 넣고, 필요한 수초·새우·균과
   구조물을 배치한다. 송사리 2마리는 보유 목록에 남겨 둔다.
2. 실행해 식물플랑크톤을 먹은 물벼룩이 번식하고 군집이 늘어나는 것을
   기다린다. 첫 새끼가 보이자마자 방류하는 대신 여러 세대가 눈에 띄게
   늘었는지 관찰하되, 특정 개체 수를 강제하는 잠금 조건은 두지 않는다.
3. 일시정지한 뒤 보유 중인 송사리를 수조에 방류하고 다시 실행한다.
4. 송사리의 물벼룩 포식, 새우의 회피와 돌 틈 이용, 이후 각 개체군의
   세대 연결을 함께 관찰한다.

이 순서는 적은 초기 물벼룩과 송사리를 처음부터 동시에 놓아 물벼룩이
번식하기 전에 전멸하는 상황을 기준 난이도로 삼지 않기 위한 것이다.
완료 조건이 정해지기 전까지는 권장 운영 순서이며 별도의 채점 문턱은
아니다.

실행 중 보유 목록에는 현재 큰물벼룩 수와 후손 성체 수, 여러 세대가
늘어나는 정도를 해석한 준비도 문구를 표시한다. 실행 중에는 방류하려면
일시정지하라고 안내하고, 일시정지하면 남겨 둔 송사리를 사용자가 직접
놓을 수 있다. 준비도 문구가 낮아도 송사리 카드를 잠그지 않으며, 문구가
높아져도 자동으로 송사리를 꺼내거나 놓지 않는다.

### 8.2 국소 포식자 단서에 대한 물벼룩 생애 반응

송사리가 만드는 국소 위험 단서를 받은 물벼룩은 포식 위험에 맞춰 성숙과
번식의 시간 배분을 바꾼다. 강한 단서에서는 성숙까지 필요한 탈피 횟수와
성숙 구조량이 조금 줄고, 충분히 먹은 개체는 번식 시작과 한 번의 육방에
더 적극적으로 물질을 배분할 수 있다. 단서가 없는 미션 1–7 수조에는 이
반응이 생기지 않는다.

위험 단서는 물질이나 먹이가 아닌 행동 정보다. 단서가 성숙·번식 기준을
바꾸더라도 섭식하지 않은 생체량을 만들지 않는다. 성체 생존에 필요한
최소 구조량은 유지하며, 새끼는 어미가 실제 섭식·동화해 번식 저장량으로
보존한 물질이 한 개체의 출생 구조량을 전부 부담할 때만 태어난다. 따라서
강한 단서의 최대 육방 수가 늘어날 수 있어도 미지급 새끼를 만들거나
탄소·질소·산소 등가 장부를 우회하지 않는다.

위험 단서와 별개인 기본 번식에서는 주변 식물플랑크톤 농도를 두 번째
곱셈 문턱으로 사용하지 않는다. 여과량은 이미 실제 국소 농도의 포화 반응을
따르고, 번식 배분은 그 순간 어미가 실제로 동화해 유지비를 넘긴
식물플랑크톤 잉여·보호 저장량·어미 상태로 다시 제한된다. 주변 농도를
한 번 더 곱하면 같은 먹이 부족을 이중 감점해, 양의 순잉여가 있는
어미도 세대를 교체하지 못했다. 제거한 것은 이 중복 계수뿐이며 먹이,
번식 물질이나 개체 수를 추가하지 않는다.

### 8.3 송사리의 짝 탐색과 구애

암컷과 수컷이 같은 거리 안에서 서로 가장 가까운 상대를 대칭적으로
추적하는 방식은 사용하지 않는다. 산란 가능한 암컷이 내는 국소 신호를
성숙한 수컷이 먼저 감지하고, 수컷이 암컷에게 접근해 구애하는 방향으로
구분한다.

- 수컷의 장거리 후보 선택은 산란 가능한 암컷의 국소 후각 신호를 거리로
  감쇠한 값으로 근사한다. 후각 단서이므로 돌의 화면 실루엣이 신호를
  완전히 끊지는 않지만, 실제 구애와 교미 접촉에는 가까운 거리와 시야가
  필요하다.
- 수컷은 선택한 암컷을 매 프레임 다른 암컷으로 바꾸지 않고, 암컷 뒤·아래
  위치로 접근해 추종과 자리잡기를 수행한다.
- 암컷은 먼 수컷을 향해 장거리 이동하지 않는다. 자신의 구애 반경까지
  접근해 표시 행동을 하는 수컷 중 하나를 수용한다.
- 여러 수컷이 동시에 구애하면 거리만 보지 않고 수컷의 몸 크기와 현재
  건강·에너지 상태를 함께 비교한다. 이는 큰 수컷의 교미 우위가 암컷
  선택과 수컷 경쟁 양쪽에서 관찰된 결과를 단순화한 것이다.
- 수컷의 접근·추종 → 암컷 아래/뒤 자리잡기 → 주둥이 부근 빠른 원무 →
  나란한 접촉 순서가 화면 이동에 나타나야 한다.
- 암컷과 수컷이 서로를 같은 상대 ID로 선택하고 실제 접촉 거리 안에 있을
  때만 교미 시간이 누적된다. 가까이 있던 선택되지 않은 수컷과 교미가
  성립하지 않는다.
- 배고픈 개체는 구애 상대를 놓고 섭식을 우선한다. 번식 저장량과 수용
  상태가 준비되지 않은 암컷은 수컷을 유인하거나 받아들이지 않는다.

동일 상대와 반복 교미했을 때의 친숙도 학습은 실제 송사리에서 확인되지만,
현재 구현에는 개체쌍별 장기 기억장을 추가하지 않는다. 미션 8의 기본 한
쌍과 다음 세대에서 위 구애 순서가 안정적으로 작동하는지 먼저 검증한 뒤,
여러 성체가 공존하는 콘텐츠에서 필요성이 생기면 별도 상태로 설계한다.

### 8.4 개발용 방류 검증과 플레이 규칙의 분리

고정 fixture의 장기 검증은 첫 육방 하나만 확인한 시점에는 송사리를 넣지
않는다. 다음 조건을 모두 만족하면 안정 확인을 시작한다.

- 살아 있는 큰물벼룩 `120마리` 이상
- 창시자가 아닌 후손 `114마리` 이상
- 후손 성체 `30마리` 이상
- 살아 있는 2세대 이상 후손 `1마리` 이상

그 뒤 `300초` 동안 큰물벼룩 `96마리`, 후손 `90마리`, 후손 성체
`24마리`, 살아 있는 2세대 이상 후손 `1마리` 이상을 계속 유지하고,
마지막 `180초` 안에 2세대 이상 새 출생도 있어야 한다. 이때만 개발용
검증기가 계산을 일시정지해 송사리 2마리를 후속 방류하고 장기 먹이망
구간을 시작한다.

이 수치는 반복 가능한 개발 fixture의 방류 시점을 고정하는 수락선이지
미션 완료 조건이나 플레이어 배치 잠금이 아니다. 검증기의 자동 일시정지와
배치는 테스트 자동화에만 존재한다. 실제 게임은 개체를 보충하거나 위
수치로 끌어올리지 않으며, 준비도 권고를 보고 언제 방류할지는 사용자가
정한다. 송사리 방류 뒤 모든 종의 세대 유지까지 포함한 최종 장기 결과는
아직 재검증 중이며 통과로 기록하지 않는다.

## 9. 송사리 외형 전면 재제작

현재 송사리 스프라이트는 일본송사리로 읽히는 체형과 인상이 부족하므로
부분 수정이나 확대·축소로 재사용하지 않는다. 행동·생애·물질 장부 코어와
시각 자산을 분리하고, 외형과 리깅은 실제 일본송사리 자료를 기준으로
처음부터 다시 제작한다.

- 머리부터 꼬리까지의 체형과 등·배 윤곽
- 눈, 입과 아가미 주변의 위치·비율
- 등지느러미·뒷지느러미·가슴지느러미·꼬리지느러미의 실제 배치와 형태
- 반투명 지느러미, 몸의 은빛·회갈색 계열과 손그림 질감
- 성체·어린 개체·치어가 단순 축소판으로만 보이지 않는 단계별 비율
- 정지·순항·급선회·먹이 추적에서 체형을 망가뜨리지 않는 새 2D 리깅

현재 송사리 자산의 실루엣이나 부위 비율을 새 디자인의 기준으로 삼지
않는다. 최종 그림을 만들기 전 실제 송사리 참고 자료로 실루엣 시안을
비교하고, 수조의 현재 화면 배율에서 송사리로 식별되는지 먼저 확인한다.

## 10. 계산과 갱신 원칙

- 긴 수조의 위험 단서장은 `72×20 = 1,440셀` 배열 하나만 사용한다.
  물고기 배경 단서와 새우 공격·포식 경보를 별도 격자로 늘리지 않고
  소스 세기만 다르게 같은 장에 기록한다.
- 위험 단서장은 기존 물 수송의 속도·경계 정보를 재사용한다. 생물마다
  냄새 배열을 만들거나 각 송사리의 흔적을 따로 저장하지 않는다.
- 새우와 송사리의 모든 조합을 매 프레임 비교하지 않는다. 공간 구역에서
  가까운 후보만 얻고, 포식 가능 크기 → 거리 → 접근 방향 → 시야 순서로
  값싼 조건부터 검사한다.
- 근접 진동은 거리와 상대속도에서 만든 일회성 이벤트이며 별도 유체장으로
  계산하지 않는다.
- 시야선 검사는 앞선 조건을 통과한 실제 추격 후보에만 실행한다.
- 틈새 연결망은 매 프레임 계산하지 않는다.
- 돌이 새로 안착하거나 이동·회전·제거되어 구조 배치가 바뀐 뒤 한 번
  다시 계산하고 캐시한다.
- 각 생물에 완전한 내비게이션 메시나 군집 경로 시스템을 따로 만들지
  않는다.
- 평상시에는 기존 국소 조향을 유지하고, 위협받은 개체만 주변 입구와
  짧은 경로를 조회한다.
- 물벼룩의 나사말 차폐 표본은 광량 계산의 수관 외곽과 성장 크기 캐시를
  재사용한다. 수관을 공간 구역에 넣어 국소 표본마다 모든 포기와 잎
  곡선을 다시 계산하지 않는다.
- 돌 이동으로 사용 중인 틈이 사라지면 내부 개체를 가장 가까운 열린 물속
  또는 연결된 표면으로 자연스럽게 내보낸다.
- 큰 수조의 `72×20` 물질·수온·흐름 계산과 틈새 캐시 갱신을 포함해
  `64배속` 장기 성능을 별도로 검증한다. 다수 송사리·새우 부하에서도
  전수 개체쌍 비교나 개체별 위험장이 생기지 않는지 회귀 검사한다.

첫 구현의 틈 후보는 안착한 두 구조물 외곽선 사이의 가장 가까운 구간에서
만들고 `6` 이상 `48` 이하의 실제 빈 폭만 저장한다. 새우와 송사리는
종 이름이 아니라 현재 몸길이에서 계산한 몸 두께가 그 폭에 맞는지 비교한다.
피식자는 맞고 현재 추격자는 맞지 않을 때만 상대적 피난처로 인정한다.

## 11. 공간 판정 검증

실험실의 `공간 판정 보기`를 켜면 현재 판정 자료를 실제 수조 화면에
겹쳐 표시한다. 일반 미션에는 표시하지 않으며, 버튼을 끈 동안에는 생물별
디버그 자료를 스냅샷에 싣거나 틈 표시를 위해 추가 계산하지 않는다.

| 색·표시 | 뜻 |
|---|---|
| 자홍색 외곽선 | 돌 배치 물리와 틈 산출에 쓰는 충돌 외곽 |
| 초록색 점·원 | 조류와 균막이 부착되고 표면 섭식 목표가 되는 생태 셀 |
| 노란색 선·끝점 | 두 구조물 사이에서 실제로 산출한 가장 가까운 틈 입구 |
| 노란색 원 | 안전 여유를 적용한 틈의 유효 몸 두께 |
| 청록·파란색 원과 지름선 | 각 생물의 현재 몸길이에서 계산한 몸 두께 |

돌이 움직이거나 사용자가 들고 있는 동안에는 아직 확정되지 않은 틈을
보여 주지 않는다. 구조물이 다시 안착하면 틈 캐시와 표시가 함께
갱신된다. 현재 첫 구현은 두 구조물 사이의 최소 간격과 몸 두께를 검증하는
도구이며, 이후 필요하면 선택 개체 기준의 `통과 가능/불가` 색상과
열린 물속·표면·틈 경로 연결선까지 확장한다.

이 화면에서 기존 돌과 작은 돌 후보를 함께 배치해 다음을 확인한다.

1. 큰 생물이 같은 화면 좌표의 앞쪽 물속을 지나갈 때 보이지 않는 벽이 없다.
2. 표면에 붙은 조류를 새우가 계속 먹을 수 있다.
3. 작은 새우가 틈에 들어가도 계속 선명하게 보이며 접근 판정만 보호된다.
4. 현재 몸이 맞지 않는 송사리는 틈 속 먹이를 포획하지 못하고, 맞는
   작은 송사리는 실제 입구를 통해 접근할 수 있다.
5. 돌을 다시 배치하면 통과 영역과 입구가 정확히 갱신된다.
6. 화면에서 납득할 수 있는 새우 전용 틈이 실제로 만들어진다.

작은 돌의 미션 지급량, 몸 두께·입구 판정 여유의 최종 보정, 송사리의
추격·포획 수치와 미션 8 완료 조건은 큰 수조 장주기 결과를 확인한 뒤
각각 별도로 논의한다.

- 실제 일본송사리 체형을 기준으로 외형·생애 단계·2D 리깅 전면 재제작

## 13. 연구·구현 참고

### 생태 관계

- [일본송사리의 물벼룩 크기 선택적 포식](https://doi.org/10.1080/02705060.2012.659222):
  송사리가 물벼룩을 주 먹이로 사용하고 먹이 크기와 생애 단계가 포획률에

  화면 개체 3마리로 압축하는 근거로 사용한다.
- [송사리 암컷 선택과 수컷 몸 크기의 교미 우위](https://pubmed.ncbi.nlm.nih.gov/9632501/):

  교미 성공에 영향을 주는 근거다.
- [같은 상대와의 반복 경험이 송사리 교미 지연을 줄이는 연구](https://www.nature.com/articles/s41598-022-23871-w):

- [물고기 단서에 대한 큰물벼룩의 조기·소형 성숙 반응](https://pubmed.ncbi.nlm.nih.gov/21146140/):
  물고기 위험 단서가 큰물벼룩의 성숙 시점과 성숙 크기 같은 생애사 배분을
  바꿀 수 있다는 근거다. 게임에서는 국소 단서가 있을 때만 적용한다.
- [포식자 종류에 따라 달라지는 물벼룩의 수초 피난](https://doi.org/10.4319/lo.2001.46.2.0230):

  사냥하는 물고기에는 효과가 사라진 결과로, 고정 안전지대 대신
  포식자 상대 차폐를 사용하는 근거다.
- [작은 시각 포식자와 수초 사이의 물벼룩 서식지 선택](https://doi.org/10.1007/s10750-023-05377-2):
  구피가 수초를 선호한 조건에서 물벼룩은 수초를 피한 결과로, 수초 자체가
  아니라 국소 포식 위험을 비교해야 한다는 근거다.
- [Daphnia–fish 개체 기반 국소 위험 모델](https://academic.oup.com/plankt/article/40/4/471/5048014):

## 14. 완료 조건

미션 8의 완료 조건은 아직 정하지 않았다. 기존 `치어 1마리 부화`, 특정
개체 수, 임의의 유지 시간이나 세대 연결을 현재 문서에서 완료 조건으로
확정하지 않는다. 큰 수조, 물벼룩 주식, 새우 피난과 송사리 포식이 실제로
작동한 뒤 무엇을 플레이어의 성취로 삼을지 별도 논의한다.

현재 플레이어블은 `긴 수조의 송사리`를 가제로 사용하며 시간 제한과 성공
판정이 없다. 표준 수조의 면적당 공급 밀도를 유지하도록 식물플랑크톤
6회, 큰물벼룩 6마리, 체리새우 8마리, 송사리 2마리, 나사말 6포기와
두 부착조류 각 8회를 첫 검증 세트로 제공한다. 송사리는 준비 단계에
함께 놓는 개체가 아니라 물벼룩이 번식한 뒤 일시정지 상태에서 방류할
보유 개체다. 이 수량과 권장 순서는 완료 조건이나 최종 난이도를 확정한
것이 아니라 실제 장주기 결과를 얻기 위한 프로토타입 시작점이다. 준비도
표시는 이 판단을 돕는 권고일 뿐 배치 잠금이나 성공 판정이 아니며, 물벼룩
자동 보충·강제 하한·송사리 자동 방류는 적용하지 않는다.
